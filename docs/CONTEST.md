## 저장소 제출 형식

[공식 지원·제출 방법](https://appdevchallenge.auto-hmg.io/guide/submission)은 소스와 APK를 함께 제공하고, `apk/` 폴더의 실행 가능한 release APK 및 README를 안내한다. README에는 앱 이름·한 줄 소개, 실행 방법, 테스트 환경·설정, APK 위치 또는 Release 링크가 필요하다.

이 저장소는 `apk/Daeho-AI_ExpeditionBoss_release.apk`와 전체 소스, 실행 안내, SDK 검증 기록을 제공한다. Releases에는 별도의 시연 APK와 Windows 시연 ZIP을 둔다. 시연 데이터와 실제 SDK 입력은 명확히 구별한다. 개발 산출물 공개와 별개로 공모전의 필수 접수양식 제출은 필요하다.

|---|---|---|
| 차량특화성 | 순정 내비 안내·차량 속도·P 기어·화면 제한을 함께 읽어 이동 중 자동 원정과 주차 후 육성을 분리 | 실차 속성 지원, 제한속도 데이터, 장시간 동작 |

사업 확장은 가설이다. 광고·유료 상자·결제는 현재 구현하지 않았다. 이용자 수나 리텐션을 실측한 것처럼 제시하지 않는다.

## 차량용 앱 설계와 심사

[주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)를 참고해 P 기어와 `CarUxRestrictions`를 확인하고, 주행 중 육성 UI를 잠근다. 속도 증가에 따라 초당 보상을 높이지 않고, 제한속도 초과·데이터 단절 시 공격을 멈춘다.

다만 [게임을 포함한 미디어 앱의 심사 기준](https://document.pleos.ai/docs/pleos-only/distribute/app-review-guide/review-driver-distraction-elements)은 주행 중 앱 사용 중지와 UI 숨김을 요구한다. 현재 구현의 **백그라운드 전투 계산**이 허용되는지는 확인되지 않았다. UI 차단만으로 기준 충족을 주장할 수 없으며, 허용되지 않으면 이동 데이터 기록과 주차 후 보상 계산으로 실행 구조를 재검토해야 한다. 이 대안은 아직 구현하지 않았다.

알림이 있는 기록 서비스는 사용자가 자동 원정을 켤 때 시작한다. 현재 사용하는 `specialUse` foreground service의 허용 여부와 장시간 유지도 대상 차량 및 심사에서 확인해야 한다.

## 제출물에서 주장할 수 있는 범위

- **구현 완료:** 보스·상자·장비·강화·도감, 저장 복구, 주차 조건에 따른 조작 제한, 실제 SDK 연결 코드.
- **에뮬레이터에서 확인:** 공식 NaviHelper 안내 모드 및 가상 차량의 SDK 전달 경로, 속도·기어·UX 제한, 백그라운드 콜백.
- **미완료:** 실차 시험, 유효 제한속도 기반 전체 전투, 마켓 허용 판단, 시장성 실측, 출시용 개인정보·스토어 등록 절차.

게임 화면과 APK가 있다는 사실을 전체 차량 환경 검증이나 안전 효과의 증명으로 표현하지 않는다.
