# 0.4.0 캐릭터와 전투 화면 검증

검증일: 2026-11-15. `versionName=0.4.0`, `versionCode=4`.

## 구현한 변화

- 왼쪽 캐릭터와 오른쪽 보스가 대치하는 전투 화면. 실제 보스 체력 변화에 맞춰 공격·피격·처치 연출을 표시한다.
- 검의 베기, 망치의 내려찍기, 창의 돌진, 지팡이의 마법탄. 실제 장착 무기의 종류로 동작을 선택한다.
- 무기·방어구·장신구의 외형과 등급색, +3 강화 발광, +5 강화 입자, 레벨 10 이후 장식. 전투 화면과 장비 미리보기가 같은 장착 데이터를 사용한다.
- 6종 보스와 각각의 배경, 실제 상자 보상을 보여 주는 장비 등장 연출, 레벨 상승·필살기 연출.
- 장착 미리보기는 확인 전까지 전투 능력치를 바꾸지 않는다. 강화는 기존 코인·가루를 소모하고 기존 저장 규칙을 따른다.

전투 연출은 게임 결과를 보여 주는 화면이다. 별도 피해·경험치·상자를 지급하지 않으며, 기존 공격력·체력·보상·성장 규칙을 변경하지 않았다. 새 적 AI나 실시간 조작 전투를 추가한 버전은 아니다.

총 단위 37개와 기기 14개. [저장](instrumentation-storage.txt), [화면](instrumentation-ui.txt), [상점](instrumentation-commerce.txt), [교환](instrumentation-social.txt), [SDK](instrumentation-odometer.txt) 기록을 제공한다. 새 장착 시험은 지팡이를 미리보기만 할 때 기존 검이 유지되고, 확인 후 장착과 +2→+3 강화·재화 차감이 저장되는지 검사한다.

처음 cold boot 직후 화면 시험 한 건은 Activity가 RESUMED로 올라오기 전에 시작되어 본문 진입 전 실패했다. 앱 시작을 기다린 뒤 같은 화면 시험 4개를 다시 실행해 모두 통과했다. 시험용 저장 상태는 원래 상태로 복원하며, 촬영에는 기존 시연 캐릭터를 사용했다.

## 차량 연동과 실행 범위

Vehicle SDK 2.3.2의 `getOdometer()`·`checkCurrentDistanceDrivenCapabilities()`·`getCurrentDistanceDriven()`으로 누적거리(km)를 읽는다. 공식 에뮬레이터에서 관측한 값은 [sdk-odometer-0.4.json](sdk-odometer-0.4.json)에 있다. NaviHelper 3.0.5는 안내 상태 진단에 사용한다. 기어와 화면 제한은 AAOS에서 확인한다.

주행이나 앱 이탈 시 전투 루프와 게임 화면을 제거한다. 주차 후 복귀 시 최대 8시간의 기본 결과를 정산하고, 확인한 이동거리로 한 번의 필살기를 적용한다. 거리당 피해·중복 정산 방지 등의 상세 규칙은 [0.3 구현 기록](UPGRADE_0_3.md)과 같다.

영상의 10km 이동은 **fixture 가상 입력**이며 실제 SDK 이동 관측과 구분한다. 실제 SDK에서 0km를 읽은 장면을 10km 실제 주행으로 설명하지 않는다. 촬영 시 앱에서 내보낸 [SDK 수신 상태](sdk-visual-0.4.json)와 [90초 영상의 촬영 범위](../DEMO_VIDEO.md)를 참고한다.

환경: 공식 Pleos Connect Emulator 2.1.0, API 34, x86_64, 2560×1440, 160dpi, RAM 4GB, SwiftShader. 상점·교환 서버는 포함된 PC 서버로 시험했다. 공개 운영 서버는 제공하지 않는다.
