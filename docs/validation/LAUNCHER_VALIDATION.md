# Windows 실행기 검증 — 2026-11-07

Windows PowerShell 5.1에서 `demo.cmd`와 같은 실행기를 호출하는 로컬 바로가기로 확인했다.

## 확인한 원인과 수정

- ADB가 연결 서비스를 처음 시작할 때 정상 안내를 stderr로 출력한다. 기존 실행기는 이를 중단 오류로 처리했다. ADB 출력을 수집하고 종료 코드로 성공 여부를 판단하도록 바꿨다. 기기 없음·부팅 중 상태는 대기 과정으로 처리한다.
- Pleos가 숨겨진 앱 작업을 유지해, 실행 성공·프로세스 존재만으로는 게임이 화면 앞에 나타났다고 판단할 수 없었다. 설치 후 게임 앱의 작업만 다시 열고, 해당 Activity가 실제로 resumed 상태인지 확인한다. 게임 데이터는 삭제하지 않는다.
- 기기를 준비하는 중 중복 실행을 막고, 이미 부팅 중인 같은 기기는 이어서 기다린다. 한국어 진행 안내와 실패 기록을 제공한다.
- 화면 없이 켜진 시험 기기는 종료 후 보이는 창으로 전환하는 경로를 추가했다. 이 전환 경로는 이번 수동 검증에 포함하지 않았다.

## 검증 결과

- **완전히 꺼진 상태:** 에뮬레이터와 ADB 서비스를 모두 종료한 뒤 실행 파일 하나로 부팅·설치·게임 전면 표시까지 확인했다.
- **부팅 중 다시 실행:** 두 번째 실행은 대기 안내만 표시했고, 에뮬레이터 프로세스는 한 개였다.
- **이미 켜진 상태:** 같은 실행 파일로 다시 게임을 열었다.
- **실제 보이는 Windows 창에서 조작:** 가상 운행으로 보스 처치와 레벨 2→3 상승, 상자 개봉으로 코인 85→122 및 잎사귀 외투 획득, 장착 후 최대 체력 100→110을 확인했다. 재부팅 후에도 유지됐다.

위 게임 동작은 명시적인 **시연 데이터 모드**에서 확인한 결과다. 차량 API 연결 기록은 [SDK_VALIDATION.md](SDK_VALIDATION.md)를 참고한다.

## 0.2.0 재확인 — 2026-11-10

친구 서버 환경 설치를 `setup.cmd`에 추가했다. 준비된 기기에서 `demo.cmd`와 같은 실행기를 호출해 PC 친구 서버가 준비되고 새 게임 버전이 전면에 열리는 것을 확인했다. 서버 DB와 게임 진행을 유지한다. [업데이트 검증 기록](UPGRADE_0_2.md)에 추가 기능의 결과를 정리했다.

현재 배포 실행 파일은 저장소 루트의 `demo.cmd`다. 실행 기록은 각 사용자의 저장소 `work/launcher-last.log`에 생성하며 공개 저장소에는 포함하지 않는다. 최초 준비는 `setup.cmd`로 수행한다.
