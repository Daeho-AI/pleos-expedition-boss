# 0.6.0 전체 전투 화면과 게임 흐름

2026-11-15 기준. 기지의 작은 전투 패널을 제거하고, 실제 보스전 진입과 처치·전리품·다음 원정 화면을 연결했다.

## 바뀐 동작

1. 원정 기지에서 차량 여정·성장·현재 구역을 확인하고 **보스전 입장**을 누른다.
2. 일반 헤더와 메뉴가 사라진다. 보스 등장 화면을 거쳐 Pleos가 배정한 앱 창 전체가 전투장으로 바뀐다.
3. 보스는 위, 수호자는 아래에 배치한다. 장착 무기별 투사체·피격 효과·체력바·피해 숫자가 실제 저장 상태를 따른다.
4. 엔진이 해당 보스의 처치 상자를 저장해야 승리 화면을 표시한다. 화면 전환 중에는 처치한 보스를 유지하고 다음 보스를 미리 표시하지 않는다.
5. 전리품 화면에서 실제 상자를 열고 장착하거나 장비·강화로 이동할 수 있다. 중복 장비는 원래 규칙대로 강화 가루로 바뀐다.
6. 조작 없이 8초가 지나면 현재 진행 중인 보스의 등장·전투 화면으로 돌아간다. 미개봉 상자는 보관되며, 화면 전환·상자 확인 중에도 주차 중 자동 사냥 계산은 이어진다.
7. 주행·백그라운드에서는 모든 게임 화면과 실행을 중단한다. 주차 후 복귀 시 기존 시간·거리 정산을 적용한다. 지난 승리 화면이나 보상을 다시 지급하지 않는다.

## 확인 범위

- Pleos Connect 2.1 / API 34 공식 에뮬레이터에서 넓은 앱 창과 순정 내비 옆 분할 창을 확인했다. 전투는 앱 창 내부를 모두 사용한다.
- `FixtureJourneyUiTest` 7개: 전체 화면 진입·기지 복귀, 실제 처치 후 보상·장착·다음 보스, 무조작 다음 전투와 미개봉 상자 보관, 주행 차단·복귀, 백그라운드 중단·복귀, 장비 미리보기·강화, 복귀 보상·도감.
- `CommerceUiTest` 1개: 기존 상점 구매 확인 및 친구 화면 회귀 확인.
- 실제 처치 테스트는 잔여 체력을 낮춘 시험 상태를 만든 뒤 라이브 엔진이 처치하도록 한다. 전투 화면 자체는 피해·상자를 생성하지 않는다.
- 코어 게임 로직은 변경하지 않았다. 빌드의 기존 단위 테스트 37개 결과는 Gradle의 `UP-TO-DATE` 재사용이다.
- fixture/debug, SDK/debug, 서명된 SDK/release APK를 빌드했다. release lint는 오류 0개, 경고 18개다.
- SDK 연결부·권한·게임 계산식·서버 계약은 이번 변경에서 수정하지 않았다. 실제 SDK 수신 기록은 `sdk-visual-0.6.json`에 별도로 보관한다.

기기 테스트 로그: [게임 화면](instrumentation-ui.txt), [상점·친구 화면](instrumentation-commerce.txt). [Lint 기록](lint-0.6.txt).

## 촬영과 데이터

90초 영상은 실제 앱 캡처와 실행 녹화를 편집한 것이다. 기존 시연 진행 데이터를 백업하고, 15레벨 장비 상태와 체력이 가득 찬 첫 구역 보스를 촬영용으로 구성했다. 전투 피해율·상자 확률·지급 규칙은 바꾸지 않았다. 촬영 후 원래 진행 데이터를 복원한다. 7분·10km 복귀는 fixture 입력이며 SDK 실수신 장면과 구분한다.

내비 지도에 게임을 덧그리지 않는다. 속도에 따른 보상, 주행 중 게임 화면, 주행 중 전투 서비스는 제공하지 않는다.
